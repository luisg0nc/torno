# Named sets: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The person gathers faces, edges, parts and sketch strokes into a **named set** (`Ctrl+G`: a name, a comment, a
colour). The set lives in `.torno/sets.json`, travels in git and is found again after every build: by the selector the
kernel made for each face or edge, else by point and normal. The person and Claude point at it as `#deck` (or
`block/#deck`, one part's members) in every tool. Claude can propose a set, which the person accepts or dismisses, and
"Make it a tag" asks Claude to write the set into `tags(p, parts)`.

**Architecture:**
- The kernel's `selectors.py` builds each selector from a **structured form** (prefix, terminal) and makes its text
  from that form alone. `selector_for` answers the form beside the text. A new `refind.py` answers one `refind` query
  per layout. It rebuilds each stored form, checks the face, and falls back to the nearest face (or edge) by point and
  normal. A `selectors` query gives the forms of several faces of one part in one pass.
- Pure rules live in a new `shared/sets.ts`: types, names, refs, `expandSet`, lost counts, the tag prompt. It sits
  beside `shared/tags.ts`, and `shared/groups.ts` stays the model's.
- Main has a new `main/sets/`, laid out as `main/marks/`: `file.ts` (the sanitiser), `store.ts` (`SetStore`, the one
  writer), `refind.ts` (after each build), `ipc.ts` (handlers without Electron) and `text.ts` (what Claude is told).
- Sketch strokes gain stable ids `k<n>`, given by `MarkStore.saveSketch`, so that a stroke member `M7/k3` names the
  same stroke after edits.
- In the window, a small `useSets` store (`renderer/state/sets.ts`) is fed by `sets:changed`. The popover is
  `ui/sets/MakeSet.tsx`, the Layers rows are `ui/sets/SetRows.tsx`, the set scope is in `state/tools.ts`, and a `set`
  highlight layer is in `viewport/highlight.ts`.

**Tech stack:** Python (build123d, OCP), Electron, TypeScript, React, three.js, pytest, vitest, Playwright (hidden window).

**Spec:** `docs/superpowers/specs/2026-11-17-sets-design.md`. Read it whole, "Builder's questions, settled" most of all.

## Global Constraints

- **The word "group" stays the model's.** `groups(p)`, `PartGroup`, `shared/groups.ts`, "Show only this group" and the
  layer headers of groups are unchanged. Every text a person or Claude reads says **named set**. Code identifiers use
  `set` and `NamedSet`, never `group`. The section in Layers is "Named sets".
- `<object>/.torno/sets.json` has one writer, main (`main/sets/store.ts`). It makes one change at a time, written
  atomically (`writeFileAtomic`). Set ids are `N<n>`, given by main from `next` and never reused, after a delete and
  after a pull too (the sanitiser raises `next` above every `N<n>`). The file travels in git and gets no
  `.torno/.gitignore` line.
- `state`, refreshed refs, `selector`, `type` and `arranged` of a member are main's. They are never taken from the
  window or a tool. `by` and `proposed` are main's too: only `sets:accept` (the person) clears `proposed`.
- **The kernel never evaluates a text it did not make.** `sets.json` holds each selector as its structured form, never
  as Python. The kernel checks every field of a form against a fixed list (the prefixes `type`, `axis`, `at`, `radius`
  and `size`; the terminals `only`, `end` and `group`; axes 0 to 2; ends 0 and -1; `GeomType` names from the enum;
  finite numbers) and writes the text itself with `_n`. A form that fails any check is no form, and the member is found
  by point and normal.
- **"By order" forms are not stored.** `selector_for` gives no `form` for a `by order` selector. The sanitiser and the
  kernel refuse an `order` terminal.
- **A selector's face is accepted only when its surface type matches the stored `type` and its normal, at the point
  nearest the stored point, is within 10° of the stored normal** (`NORMAL_DEGREES = 10` in `refind.py`). An `only`
  prefix must give exactly one face. Anything else falls to the point and normal rule: the nearest face within the
  part's `tolerance(bbox)` whose normal is within 10°. For an edge, the nearest edge within `EDGE_TOLERANCE_MM` of the
  stored point. A member found by neither is `lost` and keeps its last point and normal.
- A set belongs to one layout. Its points are in that layout's object frame, and each member records `arranged` as
  an anchor does. A ref to it from another layout is refused: `#deck is of layout assembly`.
- Names: 1 to 40 characters, starting with a letter, with no `/`, `#` or `@`, trimmed. They are unique per project,
  compared case-insensitively.
- **Colours:** 8 tokens, `--set-1` to `--set-8`, in `styles/tokens.css` (light and dark), muted, and none red or green
  (each at least 30° of hue from `--user-mark` and `--agent-mark`, held by `shared/contrast.test.ts`). A new set takes
  the next in turn (`colour = count % 8`). Colours come from the tokens and `viewport/theme.ts` only.
- New key: `set.make` = `Ctrl+G`, scope `window`. `keys.test.ts` checks every scope.
- UI text is sentence case. Numbers and refs (`#deck`, `N3`, `M7/k3`) are set in the monospace face, numbers through
  `shared/format.ts`. No per-frame state in React.
- Every number told to Claude is the kernel's and says whether it is exact. A set's `lost` count is a count, not a
  measure.
- Tests never open a visible window (`TORNO_TEST=1`, `show: false`), never call `page.screenshot()`, never use the
  clipboard, and never run the real `claude` (`TORNO_AGENT_CMD` is the stand-in).
- Commits end with the `Co-Authored-By: Claude <noreply@anthropic.com>` trailer, as this repo's `CLAUDE.md` asks.
- Before changing a file, read the `.claude/rules/` files whose `paths:` cover it: `kernel-supervisor`,
  `kernel-model-contract`, `kernel-measures`, `marks-store`, `left-column`, `mcp-tools`, `mcp-read-tools`,
  `agent-prompt`, `keys`, `chat-cards-and-refs`, `styles-themes`. A change to what torno does changes the manual
  (`docs/manual.md`) and the rule that says it, in the same commit.

## Review Focus

1. **A rebuild that renumbers the faces:** after a model edit that puts new faces before the set's, `block/F12`
   becomes `block/F15`. The set names `F15` (found `selector`), its state is `ok`, and `#deck` in `describe` gives the
   same face. With the selector broken by the edit, it is found `nearest` (Tasks 1 and 3, and the e2e in Task 9).
2. **A face whose only selector is by order:** no `form` is stored, and refind goes by point and normal. A stored
   form whose face now has another type, or a normal 15° off, is not accepted. A hand-edited `sets.json` with an
   `order` terminal, or a form holding text (`"type": "PLANE) or True or (1"`), is dropped by the sanitiser and refused
   by the kernel, and nothing is evaluated (Tasks 1 and 2).
3. **A set across layouts:** a set of `assembly` is refound only in `assembly`. `#deck` in `measure`, `highlight` or
   `add_mark` with `layout: 'print'` is refused with `#deck is of layout assembly`. A print layout that spreads its
   parts differently moves the members' points by the difference before refind (Tasks 3 and 5).
4. **Erasing a stroke a set holds:** the member `M7/k3` is lost (`1 of 3 strokes lost`), and it is never refound by a
   new stroke. The next stroke drawn is `k4`, not `k3`, after an undo too, and removing `M7` loses every stroke member
   of it. Nothing about strokes is written to `sets.json`: their state is read from the marks (Tasks 4 and 5).
5. **Claude's proposal used before it is accepted:** `add_set` makes `N4` with `by: 'agent'` and `proposed: true`.
   `#intake` works at once in every tool, and every reply and `scene` says `proposed by you, not accepted`. No tool can
   accept it, and a second `add_set` with that name is refused. Dismiss deletes it, and a mark placed on it meanwhile
   keeps `set: '#intake'` as a label and stays where it is. Accept makes it `by: 'person'`, with no `proposed`
   (Tasks 2, 6 and 8).

### Task 1: Structured selector forms, and the kernel's `selectors` and `refind` queries

**Files:**

- Modify: `kernel/src/torno_kernel/queries.py` (`run` dispatches `selectors` and `refind`, and the unknown-query list

- Test: `kernel/tests/test_selectors.py`, `kernel/tests/test_refind.py` (new)

**Interfaces (produces):**
- A form is plain JSON, the same pairs the search makes today:
  - `{"of": "faces" | "edges", "prefix": Prefix, "terminal": Terminal}`
  - `Prefix` is one of:
    - `{"by": "type", "type": "PLANE"}`
    - `{"by": "axis", "axis": 2}`
    - `{"by": "at", "type", "center": [x, y, z]}`
    - `{"by": "radius", "type", "radius"}`
    - `{"by": "size", "type", "size", "within"}`
  - `Terminal` is one of `{"only": true}`, `{"end": axis, "at": 0 | -1}`,
    `{"group": a, "at": 0 | -1, "then": b, "thenAt": 0 | -1}` or `{"order": axis, "index": i}`. The last is made by
    the search and never answered as a form.
- `parse_form(raw: Any, kind: str) -> dict | None`: the form checked field by field (see Global Constraints), or None.
  It never raises.
- `expression_of(form: dict) -> str`: the text, written by the same helpers `_candidates` uses today, so that every
  expression `describe` gives is byte-for-byte what it gave before.
- `selector_for(...)` answers `{"selector": {"expression", "robust", "checked", "form"?}}`. `form` is present only for
  `by geometry`.
- `selectors` query: `{"layout": str, "refs": [str]}`, refs of one part. It answers
  `{"selectors": [{"ref", "type", "center", "normal"?, "selector": {...} | None, "selectorWhy"?}]}`. `normal` is a
  face's at its centre's nearest point. All refs share one budget, `SELECTORS_BUDGET = 20.0` s. Refs past it answer
  `selector: None` with `selectorWhy: "out of time"`.
- `refind` query: `{"layout": str, "members": [{"part", "kind": "face" | "edge", "type"?, "form"?, "point", "normal"?, "within"}]}`.
  It answers `{"members": [{"found": "selector" | "nearest" | "lost", "ref"?, "point"?, "normal"?, "type"?, "why"?}]}`
  in the same order. `within` is mm and is main's (`tolerance(bbox)` for a face, `EDGE_TOLERANCE_MM` for an edge). A
  part the layout lacks is `lost` with `why: "no part block in layout assembly"`. The kernel checks each member as
  `_anchor` does, and one bad member is a `bad_request` naming its index.
- `refind.NORMAL_DEGREES = 10.0`.
- `_Surface.nearest_facing(key, point, normal, within, degrees) -> int | None`: the face index.
- `_Surface.nearest_edge(key, point, within) -> int | None`: the edge index.
