# 3D sketches: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Draw makes a 3D sketch: one mark of kind `sketch` holding many strokes in millimetres on faces, on planes and
between snapped points, with a name, a comment and `take` (exact, rough, flow, with an optional diameter). It goes to
Claude with the next prompt, shows in 3D and on the board, and Claude can make its own with `add_sketch`.

**Architecture:**
- The kernel adds exact snap data (B-rep vertices, circular edges' centres) to each part's mesh.
- A new mark kind in `shared/marks.ts`, stored by `MarkStore`. The window sends whole sketches through `marks:sketch`.
  Main checks snaps against the build's snap data, works out what each stroke touches, and writes the mark.
- The card picture is drawn by the window and kept by main in `.torno/notes/`, as view notes keep theirs.
- The renderer's Draw tool becomes the sketch tool. Pure modules (planes, snapping, pens) sit under
  `renderer/tools/sketch/`, the 3D display goes in `viewport/marks/`, and the panel goes in `ui/sketch/`.

**Tech stack:** Electron, TypeScript, React, three.js, vitest, Playwright (hidden window); Python, build123d,
ocp-tessellate, pytest.

**Spec:** `docs/superpowers/specs/2026-11-17-3d-sketches-design.md` (read it whole; the mockups are Sketch-B and
Sketch-C on the design canvas).

## Global Constraints

- Main is the only writer of `marks.json`: one change at a time, atomic. `MAIN_ONLY_KEYS`, `touches`, `picture` and ids
  are never taken from the window or a tool.
- Caps per sketch:
  - `name` at most 80 characters, one line
  - `diameter` greater than 0 and at most 500 mm, only when `take === 'flow'`
  - at most 200 strokes, 400 points per stroke (`MAX_STROKE_POINTS`) and 20 000 points in all
  - `add_sketch`: at most 50 strokes and 2 000 points
- Exactness:
  - A point is told as exact only when it is a vertex, a circle's centre, or a point on a straight or circular edge,
    recomputed by main from the build's snap data, within 0.01 mm.
  - Other edge snaps are `approx`.
  - Freehand points are told rounded to 0.1 mm and said to be approximate.
- Each stroke, and each face plane, carries the `revision` it was drawn on, and is told "of build N".
- A sketch open for editing is held back from prompts until Done.
- No pictures go with a prompt for a sketch: text only.
- The board's ink-pad card is called "Doodle" in everything a person or Claude reads. Code, the stored `kind` and file
  names keep `sketch`.
- Keys while sketching:
  - The view keys keep working: fit, `1`–`4`, explode, section, ortho.
  - `Ctrl` held turns snapping off. No `Alt`.
- No per-frame state in React. Colours come from tokens and `viewport/theme.ts` only. UI text is in sentence case;
  numbers and refs are in the monospace face, through `shared/format.ts`.
- Tests never open a visible window, never call `page.screenshot()`, never use the clipboard, and never run the real
  `claude`. The kernel never writes a file.
- Commits end with the `Co-Authored-By: Claude <noreply@anthropic.com>` trailer, as this repo's `CLAUDE.md` asks.
- Before changing a file, read the `.claude/rules/` files whose `paths:` cover it: `marks-store`, `marks-window`,
  `drawing-on-view`, `board`, `mcp-tools`, `mcp-read-tools`, `agent-prompt`, `keys`, `kernel-supervisor`,
  `viewport-overlay`, `exactness-app`, `chat-cards-and-refs`. A change to what torno does changes the manual
  (`docs/manual.md`) and the rule that says it, in the same commit.

## Review Focus

1. A sketch drawn on build 3, reopened on build 7 where `block/E14` no longer exists: the old strokes are kept untouched
   and still told "of build 3", and only new strokes are checked (Task 3).
2. The window sends a snapped point that is 0.5 mm off the kernel's centre, or names a `V` index past the part's
   vertices: main refuses the edit and says why (Task 3).
3. A part with a B-spline edge: snapping to it records `approx`, and Claude is never told that point is exact (Tasks 3
   and 4).
4. A prompt sent while a sketch is open: the sketch is not sent and not marked sent, and the line under the prompt says
   so. Pressing Done, then sending, sends it (Task 4).
5. A `marks.json` from before this change with `stroke` marks: they read, draw, send and resolve as before, and nothing
   makes a new one (Tasks 2 and 7).

**Interfaces (produces):**
- `PartMesh.points: Buf`: float32 xyz per B-rep vertex, part-local, in the order `V<i>` names them (`i` from 0). Use
  the same vertex order as build123d's `shape.vertices()` (a `TopExp` map). The order is documented in
  `kernel-model-contract`.
- `PartMesh.circles: Buf`: float32, 8 per circular edge: `edge, cx, cy, cz, ax, ay, az, r`, part-local. `edge` is the
  kernel's edge index as `E<i>`. This covers every edge whose curve is a circle (`GeomAbs_Circle`), whole or an arc.
- Both are optional on the TypeScript side, so an old kernel's scene still reads: absent means no snap data.
- `shared/snapdata.ts`:
  - `interface SnapData { points: Float32Array; circles: Float32Array }`
  - `vertexAt(data, i): Vec3 | null`
  - `circleOf(data, edge): { centre: Vec3; axis: Vec3; radius: number } | null`
  - `lineOf(points, edgeVertices?)`: not needed. A straight edge's ends are its two tessellated end points, which
    equal B-rep vertices within 1e-6. Main finds them through `points`.
