# The board Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Each project gets a board of cards that swaps with the 3D view, carries one line per prompt, can be attached
to a prompt in full, and is read and added to by Claude through two tools.

**Architecture:** Main owns `<object>/.torno/board/` through one store (`main/board/`), as it owns the marks: it gives
ids, places cards that appear by themselves, keeps what Claude was told, writes the text form that both an attachment
and the `board` tool use, and is the only writer. The window draws the board as page elements in one layer moved by a
CSS transform set directly (no React state per frame), with an SVG layer for arrows, a minimap, and tools.

**Tech Stack:** Electron, TypeScript, React, zustand (`createStore`, as `state/drawing.ts`), vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-16-board-design.md`

## Global Constraints

- Everything written stays under `<object>/.torno/board/`; no new write exception in the workspace.
- `board.json` travels in git; `pictures/` has its own `.gitignore` of `*`; `told.json` is ignored through `ensureIgnored`.
- Board item ids are `C<n>`, per project, given by main only, never reused. `id`, `by`, `hidden` are main's only: never
  taken from the window or a tool's arguments.
- Claude (`by: 'agent'`) never moves, edits, hides or removes a card with `by: 'person'`, nor one that appeared by itself.
- Every prompt carries one board line inside `CONTEXT_LIMIT`; an attachment's text is capped at 12 000 characters; at
  most 6 pictures go with an attachment or a `board` read, each at most 1280 px on its long edge.
- Zoom from 10 % to 400 %. Undo up to 50 board changes made in this window.
- No per-frame state in React: pan and zoom set the layer's `style.transform` directly.
- Keys are rows of `shared/keys.ts` (`keyClashes` passes): `Ctrl+Tab` swaps Board and Model (scope `window`, not in a
  text field); the tools `V`, `N`, `F`, `A`, `I`, `S` are in a new scope `board`.
- UI text in sentence case; every number and ref (`C7`, `M3`, `h41`) in the monospace face; colours from
  `app/src/renderer/styles/tokens.css`. No control-room look.
- Tests never open a visible window (`TORNO_TEST=1`, read `.claude/rules/e2e-hidden-window.md`), never run the real
  `claude`, never use the clipboard or `page.screenshot()`.
- Commits describe the change in plain words, with no Claude attribution line.

**Correction to the spec (ruling):** the spec says `board.json` is read again after an outside change "as the marks
do". The marks are read once per open and not watched (`main/marks/store.ts:66-71`). The board does the same: read when
the project is opened, and again when the workspace is opened again. Cost: a `git pull` while the project is open shows
on the next open.

**Ruling on picture scaling:** main scales pictures for Claude with Electron's `nativeImage` (`resize`), injected as a
dependency (`scale(bytes, edge): Promise<Uint8Array>`) so unit tests pass a stand-in. The window sends no picture bytes
with an attachment, only ids.

## Review Focus

1. A board with 200 auto cards (a big project's marks) opens and pans without React re-rendering cards: Task 6 counts renders.
2. `add_card` given a person's card id, a frame of the person's that is full, or a forged `by`/`id` changes nothing of the person's: Task 4.
3. A prompt that fails to deliver leaves new cards new; a delivered one clears them, Claude's own never counted: Task 3.
4. A `board.json` pulled from git with missing pictures and builds draws placeholders and sends no picture: Tasks 2 and 3.
5. Deleting a mark removes its card; hiding a card then reopening its mark keeps it hidden; a hidden card is in no text form: Tasks 2 and 3.
